# `node:v8` — compatibility plan

**Status:** implemented (unreleased, v0.16.2) · **Owner:** runtime

## Why

`execa@10` is the only remaining CLI-stack package that fails purely on a missing
builtin: it imports `node:v8` at module scope. A census of the ~hundreds of
packages in a real install (a real project's `node_modules`, 64 top-level entries)
found six that import `v8`, and none use V8 internals:

| Package | Use |
|---|---|
| `prettier`, `import-meta-resolve`, `vite`, `vitest` | `v8.startupSnapshot.isBuildingSnapshot()` |
| `@babel/core`, `jiti` | import only |
| `execa` | `v8.serialize(x)` inside try/catch, to validate that `ipcInput` is serializable; the buffer is never transmitted |

So this is a **load-time compatibility** problem, not a V8-feature problem.

## Decision

Implement `v8` as a **shim over QuickJS**, not as a backend. There is no V8
serializer or heap-snapshot format in the engine to route calls to, and two
properties cannot be reproduced at all:

- `serialize()` produces V8's undocumented, version-tagged binary format.
- `getHeapSnapshot()`/`writeHeapSnapshot()` produce V8's heap-snapshot JSON.

Everything else is shape-compatible with documented approximations.

## Surface

Node 22.11 is the emulation target. `Object.keys(require('v8'))` on Node 22 has
about two dozen names; djs implements the ten below and deliberately omits the
rest (`Serializer`, `Deserializer`, `Default*`, `GCProfiler`, `queryObjects`,
`takeCoverage`/`stopCoverage`, `promiseHooks`, `setHeapSnapshotNearHeapLimit`,
`isStringOneByteRepresentation`, `getCppHeapStatistics`, `start*Profile`).
Tier 1 means "same names and types **for the implemented subset**".

| API | djs behaviour | Class |
|---|---|---|
| `serialize(v)` | Tagged JSON envelope in a Buffer (format below); `Error` (`"<value> could not be cloned."`) for functions, symbols, WeakMap/WeakSet, SharedArrayBuffer; `ERR_BUFFER_TOO_LARGE` above 256 MiB | djs-local |
| `deserialize(b)` | Rebuilds the graph; `TypeError`/`ERR_INVALID_ARG_TYPE` for a non-TypedArray/DataView argument; `Error` "Unable to deserialize cloned data due to invalid or unsupported version." for corrupt input | djs-local |
| `getHeapStatistics()` | Node 22's 14 keys; values from `JS_ComputeMemoryUsage` plus `Runtime.memoryLimit` | shape exact, values approximate |
| `getHeapSpaceStatistics()` | one entry, Node's five keys, `space_name: "quickjs"` | shape exact, entries differ |
| `getHeapCodeStatistics()` | Node's four keys; only `code_and_metadata_size` is meaningful | approximate |
| `cachedDataVersionTag()` | constant `0x9E3779B9 >>> 0` | approximate |
| `setFlagsFromString(s)` | no-op, returns `undefined` | exact (no effect) |
| `startupSnapshot.isBuildingSnapshot()` | returns boolean `false` (Node returns `0`; see divergences) | approximate |
| `startupSnapshot.addSerializeCallback` / `addDeserializeCallback` / `setDeserializeMainFunction` | throw `Error` code `ERR_NOT_BUILDING_SNAPSHOT`, message "Operation cannot be invoked when not building startup snapshot" — Node's exact behaviour outside a snapshot build | exact |
| `getHeapSnapshot()`, `writeHeapSnapshot()` | throw `Error` code `ERR_NOT_IMPLEMENTED` | refused |

**Heap field mapping (14 keys, Node order):**

| Key | Source |
|---|---|
| `total_heap_size` | `malloc_size` |
| `total_heap_size_executable` | `js_func_code_size` |
| `total_physical_size` | `malloc_size` |
| `total_available_size` | `max(limit - malloc_size, 0)` |
| `used_heap_size` | `memory_used_size` |
| `heap_size_limit` | `Runtime.memoryLimit`; when 0 (unlimited) the 256 MiB default, so the value is always > 0 |
| `malloced_memory` | `0` — djs does not track off-heap allocations separately |
| `peak_malloced_memory` | `0` — same reason; consistent with `malloced_memory` |
| `does_zap_garbage` | `0` (a **number**, as in Node) |
| `number_of_native_contexts` | `1` |
| `number_of_detached_contexts` | `0` |
| `total_global_handles_size` | `0` |
| `used_global_handles_size` | `0` |
| `external_memory` | patched `JS_GetArrayBufferBytes` |

Node ≥ 24 adds `total_allocated_bytes`; djs stays at the 22.11 surface and
COMPAT.md says so.

`getHeapSpaceStatistics()` returns exactly
`{space_name, space_size, space_used_size, space_available_size, physical_space_size}`.
`getHeapCodeStatistics()` returns `code_and_metadata_size`,
`bytecode_and_metadata_size: 0`, `external_script_source_size: 0`,
`cpu_profiler_metadata_size: 0`.

## Serialization format

`Buffer` of UTF-8 JSON: `{"v":1,"root":<node>}`. Objects are emitted inline on
first sight with an `id`; later sightings are `{"t":"ref","i":N}`. The decoder
allocates the shell, registers it in the ref table, then fills it, so cycles and
self-referencing Maps work.

Nodes: `undef`, `null`, `bool{v}`, `num{v}` (finite numbers as numbers; `"NaN"`,
`"Infinity"`, `"-Infinity"`, `"-0"` as strings), `str{v}`, `bigint{v}`, `arr{id,v}`
where a JSON `null` slot is a **hole** (`{"t":"null"}` is a real null), `obj{id,v}`
as `[[key,node],...]`, `map{id,v}`, `set{id,v}`, `date{v}` (ms or `"NaN"`),
`re{s,f}`, `err{n,m,s,p}` (name, message, stack, own enumerable properties),
`bin{ctor,off,len,back,v}` where `v` is the base64 of the **whole backing
buffer** and `off`/`len` are the view's byte offset/length (`ctor` is one of
`ArrayBuffer`, `Buffer`, `DataView`, `Uint8Array`, `Int8Array`, `Uint16Array`,
`Int16Array`, `Uint32Array`, `Int32Array`, `Float32Array`, `Float64Array`,
`BigInt64Array`, `BigUint64Array`), and `ref{i}`.

Decoder rules: reject a version other than 1, an unknown tag, an out-of-range or
reused `id`/`ref`, and any non-object node. Object properties are rebuilt with
`Object.defineProperty(out, k, {value, enumerable: true, writable: true,
configurable: true})`, so a `__proto__` key stays an own property instead of
polluting the prototype. Symbol-keyed properties are dropped (JSON has no
representation), matching structured clone's treatment of non-enumerable data.

**Known divergences, documented rather than hidden:** trailing bytes after the
JSON value are rejected (Node ignores them); the byte format is not compatible
with Node's in either direction.

## Wiring

1. `js/prelude/08-v8.js` (concatenated in `src/djs/runtime.d:34-40`), assigning
   `g.v8`.
2. Native `__djs.process.memoryStats()` — full `JSMemoryUsage` counters plus
   `arrayBufferBytes` — added to `src/djs/apis/process.d` as an `extern(C)
   nothrow @nogc` wrapper over a `guarded!` implementation and registered in
   `installProcess` (`process.d:524-536`).
3. `classify.d`: `v8` and `node:v8` → `djs:v8`.
4. `cjs.d` `builtinValue`: `djs:v8` → `globalThis.v8`. Without this the function
   falls through to `globalThis.process`.
5. `esm.d`: a `globalThis.v8` default branch in `builtinModuleSource` (the
   fallback is `globalThis.process`) and a `v8Exports` list in
   `builtinExportNames`, or named imports fail at link time.
6. `js/prelude/06-modules.js`: add `'v8'` to `BUILTIN_MODULES`, otherwise
   `module.isBuiltin('v8')` stays false.
7. `tests/js/esm_builtin_parity/main.mjs`: add `'v8'` to the hardcoded module
   list — the parity gate does not discover modules on its own.

## Compatibility contract

1. **Shape.** Same names/types for the implemented subset; `getHeapStatistics`
   has exactly Node 22's 14 keys; the other stats objects have their five/four
   keys. Enforced by `tests/js/v8_shim.js` plus a check that
   `require('node:v8') !== require('node:process')`.
2. **Semantics.** `deserialize(serialize(x))` deep-equals `x` for primitives
   (including `NaN`, `±Infinity`, `-0`), sparse arrays, cycles, Map/Set, Date,
   RegExp, BigInt, Error, Buffer/typed arrays/DataView; `!!startupSnapshot
   .isBuildingSnapshot() === false`; `0 < used_heap_size <= total_heap_size`;
   `heap_size_limit > 0`; `total_available_size >= 0`.
3. **Values and bytes.** Not promised: serialize bytes, heap numbers, space
   names, snapshot files.

## Execution notes

Built as specified. Three load-time gaps surfaced while verifying `execa@10`
and were fixed in the same pass because they are the same class of problem:
`node:path/win32` (its `kill-descendants.js` imports it at module scope),
`timers/promises.scheduler`, `util.aborted`, `events.setMaxListeners` and
`process.execArgv`. execa 10 runs end-to-end after the async fixes in
COMPAT.md (stream iteration, `finished()`, `events.on`, `ChildProcess.stdio`
and the `'spawn'` event).
