# v0.15.0 — child_process breadth

First Tier 2 release. `spawn`/`spawnSync` already existed; this adds the
callback APIs most tooling actually calls.

## Implemented

- `exec(command, options, callback)` via `/bin/sh -c` (or `options.shell`)
- `execFile(file, args, options, callback)` built on async `spawn`
- `maxBuffer` (default 1 MiB) → `ERR_CHILD_PROCESS_STDIO_MAXBUFFER`
- `timeout` + `killSignal` → `ETIMEDOUT`, `killed: true`
- `encoding: "buffer"` returns Buffers, otherwise decoded strings
- error objects carry `code`, `signal`, `killed`, `cmd`, `stdout`, `stderr`
- `ChildProcess.exitCode` / `signalCode` populated on exit

`fork` and IPC are deliberately not in this release: they need a fourth pipe
and `process.send`/`message`, planned as a separate row together with `cluster`.

## Application review

| # | Severity | Finding | Verification |
|---|---|---|---|
| 1 | high | exec streamed output could exceed memory | `maxBuffer` kills and reports the Node code |
| 2 | high | timed-out child kept running | timer kills with `killSignal`; test asserts `ETIMEDOUT` and `killed` |
| 3 | medium | non-zero exit looked like success | `code !== 0` produces an Error with numeric `code` and captured streams |
| 4 | medium | binary output corrupted by string collection | chunks are Buffers; `encoding: "buffer"` returns a Buffer |
| 5 | low | exit metadata missing | `exitCode`/`signalCode` set before events |

## Verification

`tests/js/child_async.js` golden covers success, failure, maxBuffer, timeout
and buffer encoding. Full gate 14/14.

## Residual

No `fork`/IPC, no `detached`, no `stdio: inherit`, no `shell: true` semantics
beyond choosing the shell binary, and no Windows paths.
