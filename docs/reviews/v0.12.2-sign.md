# v0.12.2 — signatures

## Plan

Close the crypto partial with `sign`/`verify` and a minimal `KeyObject`.
Batch 3 (fs.watch, dns.resolve, vm, WebSocket, Web Streams, opendir) moves to
v0.12.3; keeping signature tests in a small release made the gate meaningful.

## Architecture

- `crypto.sign`/`verify` call `EVP_DigestSign`/`EVP_DigestVerify` twice for
  signing (size probe, then fill) and once for verification.
- Keys arrive as a PEM string, a PEM file path, or a `KeyObject` wrapper. The
  native loader detects `-----BEGIN` and uses `BIO_new_mem_buf`, otherwise it
  opens the path and applies the read permission.
- Algorithm strings strip a `RSA-`/`EC-`/`DSA-` prefix before digest lookup,
  so `"RSA-SHA256"` and `"sha256"` both work.
- `KeyObject` is a thin `{type, _pem}` wrapper; it does not export JWK or
  derive public keys from private ones.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | `permissionCheck`/`permissionThrow` were missing from the crypto imports | build | added |
| 2 | medium | signature size probing must run before allocation; using a fixed 512-byte buffer would truncate EC/RSA-4096 | design | two-pass `EVP_DigestSign` |
| 3 | low | passphrase-protected PEMs would hit OpenSSL's default prompt | design | unsupported; documented |
| 4 | low | certificate PEMs are not accepted as public keys (`PEM_read_bio_PUBKEY` only) | design | documented |
