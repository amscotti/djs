# v0.13.6 — Buffer, module resolution, stream interop

## Plan

The compatibility audit's top two blockers shipped together because both are
foundation-level and small enough to verify in one gate:

1. `Buffer` was a thin `Uint8Array` wrapper with no numeric accessors, no
   `copy`/`indexOf`, no BigInt, no `toJSON`/`swap*`, no base64url.
2. `require.resolve` did not exist, `createRequire(...).resolve` returned its
   input, and entry scripts had relative `__filename`/`__dirname` plus no
   `module`/`exports`.
3. Node streams and Web Streams could not be converted into each other, and
   `ReadableStream` was not a global, which blocks `undici`, Hono's node server
   and fetch-body adapters.

## Architecture

Buffer (prelude, no native changes):

- fixed-width 8/16/32/64 signed/unsigned LE/BE, float/double via `DataView`;
- variable-width 1–6 byte accessors; BigInt 64-bit with two's complement;
- `copy`, `indexOf`/`lastIndexOf`/`includes` (number/string/Buffer/offset),
  `swap16/32/64`, `toJSON`, `Buffer.isEncoding`;
- base64url at the JS layer, padding tolerant;
- `Buffer.from(Buffer|Uint8Array)` copies; `ArrayBuffer` still shares.

Module resolution:

- new native `__djs.resolveFrom(dir, spec)` wrapping `resolveSpec`, plus
  `require.resolve` attached to both the global `require` and every
  module-scoped `require` (function data carries the module directory);
- `createRequire` now resolves through the same native, for paths and
  `file://` URLs;
- entry CJS scripts get absolute `__filename`/`__dirname` (from the canonical
  path) and global `module`/`exports` objects, so `module.id`,
  `module.filename`, `module.exports` no longer throw.

Stream interop:

- `Readable.toWeb` bridges `data`/`end`/`error` into a `ReadableStream`;
  `Readable.fromWeb` pumps a reader into `push()`, with `{objectMode}`.
- `Writable.toWeb` / `fromWeb` bridge `write`/`end` to writer promises;
  `Duplex.toWeb` returns `{readable, writable}`; `addAbortSignal` destroys the
  stream with `AbortError`/`ABORT_ERR`.
- `ReadableStream`/`WritableStream`/`TransformStream` are globals.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | numeric Buffer accessors absent | `readUInt16BE` undefined | full accessor set |
| 2 | high | `copy`/`indexOf`/`includes` absent | TypeError | implemented |
| 3 | high | `require.resolve` absent | `typeof require.resolve` undefined | native resolve + per-module binding |
| 4 | high | entry `module`/`exports` undefined | `typeof module` threw | globals installed for script entries |
| 5 | medium | `__filename`/`__dirname` relative in entry | printed `tests/js/x.js` | canonical absolute paths |
| 6 | medium | `Buffer.from(buffer)` aliased memory | mutating source changed copy | copy views |
| 7 | medium | base64url unsupported | `toString("base64url")` threw | JS conversion |
| 8 | low | range errors lacked `code` | `e.code` undefined | `ERR_OUT_OF_RANGE` |
| 9 | high | no `toWeb`/`fromWeb`; `ReadableStream` not global | `Readable.toWeb` undefined | adapters + globals |
| 10 | medium | `toWeb` has no backpressure (queue grows) | large producer | documented, queue-based |

Known boundary: resolution is root-bounded (entry directory), so
`require.resolve("../../outside")` returns `MODULE_NOT_FOUND`. That is the
documented sandbox, not a Node parity bug.

## Verification

- `tests/js/buffer_full.js` + golden: accessors, BigInt, copy, searches, fill,
  toJSON, swaps, base64url, isEncoding, copy semantics, range codes.
- `tests/js/module_resolve.js` + golden: builtin/relative/JSON resolve,
  `MODULE_NOT_FOUND`, module-scoped `require.resolve`, entry `module`, and
  `createRequire` from both a path and a `file://` URL.
- `tests/js/stream_web_interop.js` + golden: `toWeb abc`, `fromWeb xy`,
  `objectMode 1,2`, writable both directions, abort `AbortError:ABORT_ERR`,
  Duplex pair.
- Existing `buffer_basic`, `websocket`, `http2`, `fetch_stream` still pass.

Full gate 13/13.

## Residual

No Buffer pooling/`allocUnsafe` zero-fill semantics, no `transcode`; no
`import.meta.resolve`; `require.cache`/`require.main` are not exposed.
`toWeb` backpressure is queue-based rather than pull-driven.
