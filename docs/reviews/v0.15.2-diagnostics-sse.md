# v0.15.2 — diagnostics, perf marks, EventSource

## Implemented

- `diagnostics_channel`: singleton `channel(name)`, `hasSubscribers`,
  `subscribe`/`unsubscribe`, `Channel`, and module-level helpers
- `trace_events`: `createTracing()` and `getEnabledCategories()` (tracing is
  inert; the API imports and returns `enabled: false`)
- `perf_hooks`: `performance.mark/measure`, `getEntries`,
  `getEntriesByType/Name`, `clearMarks/clearMeasures`, `PerformanceObserver`
- global `EventSource` over HTTP/HTTPS with SSE parsing (`data`, `event`,
  `id`, `retry`), `onopen`/`onmessage`/`onerror`, `addEventListener`, `close`,
  and reconnect
- `ClientRequest.abort()`/`destroy()` so SSE and other streaming clients can
  actually cancel a request

## Application review

| # | Severity | Finding | Verification |
|---|---|---|---|
| 1 | high | APM/instrumentation packages fail on import | `require("diagnostics_channel")` and `trace_events` resolve |
| 2 | high | SSE clients had no way to consume events | local SSE server delivers `message` and custom events |
| 3 | high | closing an EventSource left the HTTP request running | `abort()` destroys the socket; `readyState` becomes 2 |
| 4 | medium | `perf_hooks` only had `now`/`timeOrigin` | marks, measures and entry queries tested |
| 5 | low | diagnostics publish errors could break the publisher | subscribers run synchronously like Node; test covers delivery |

## Verification

`tests/js/diagnostics_sse.js` golden; full gate 14/14.

## Residual

- `PerformanceObserver` records are accepted but never dispatched
- `trace_events` does not emit real trace data, and `inspector`/`v8` remain
  absent pending the V8 research phase
- EventSource reconnects unconditionally on clean server end (no `Last-Event-ID`
  request header yet)
