## Architecture

- `HttpConnection` is a per-socket state machine (`head`, `fixed`,
  `chunk-size`, `chunk-data`, `chunk-crlf`, `trailers`, `waiting`) with a
  single buffer and a pump loop. One request is dispatched at a time; pipelined
  bytes stay buffered until the previous response finishes, which preserves
  response ordering without a queue.
- `ServerResponse` owns framing: it decides chunked vs `Content-Length`,
  suppresses bodies for HEAD, emits `Connection: keep-alive`/`close`, and on
  `end()` hands control back to the connection instead of always closing the
  socket.
- Timeouts are enforced with `socket.setTimeout`: `headersTimeout` while
  parsing, `requestTimeout` while reading a body or running a handler,
  `keepAliveTimeout` while idle. A timeout destroys the connection.
- Graceful close stops accepting, destroys idle connections and lets busy ones
  finish; the callback fires when the connection set drains.
- `child_process` timeout uses `poll` with a computed deadline; both timeout
  and maxBuffer kill the child with `SIGKILL`, then truncate buffers to
  `maxBuffer` and attach an `ETIMEDOUT`/`ERR_CHILD_PROCESS_STDIO_MAXBUFFER`
  error object.
- `fs.createReadStream` slices Buffer payloads by `highWaterMark` (previously
  only strings were chunked).

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | responses always forced `Connection: close`, so clients could not reuse a socket | two requests on one socket | keep-alive negotiation from HTTP version + `Connection` header |
| 2 | high | request bodies were only `Content-Length`-framed and the remainder after a body was discarded | chunked POST, pipelined requests | chunked decoder + persistent buffer with exact consumption |
| 3 | high | HEAD responses wrote a body despite `Content-Length` | `curl -I` | `_head` suppresses body writes |
| 4 | medium | `server.close()` never drained busy connections and could call back before they finished | close during an in-flight request | connection set + pending-close callback |
| 5 | medium | maxBuffer detected overflow after appending the whole read, so `stdout` exceeded the cap | `head -c 200000` with `maxBuffer:1000` | truncate both buffers to `maxBuffer` |
| 6 | medium | `execSync` lost `r.error`, so timeouts surfaced as a generic "Command failed" | `execSync("exec sleep 2",{timeout:150})` | rethrow `r.error` with stdout/stderr/status attached |
| 7 | low | timeout result reported numeric `9` instead of `SIGKILL` | spawnSync timeout | signal string set after the numeric assignment |
| 8 | low | `fs.createReadStream` pushed a whole Buffer as one chunk | 200 KB file | slice by highWaterMark |

Notable non-finding: chunked responses already worked and continue to work;
the state machine's `0\r\n\r\n` terminator is only written for non-HEAD.
