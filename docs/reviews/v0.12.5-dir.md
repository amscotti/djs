# v0.12.5 — fs.opendir and watchFile

## Plan

Close the `fs` directory-iteration gap and add the polling fallback for
filesystems where inotify is unsuitable. `vm` and Web Streams move to v0.12.6;
`vm` needs a real second QuickJS context, which the runtime does not expose
yet.

## Architecture

- `Dir` lists entries eagerly with `readdirSync` and serves them through
  `readSync()`, returning a fresh entry object with lazy `isFile`/
  `isDirectory` (one `stat` per entry, cached). There is no OS directory
  handle, so `close` is bookkeeping.
- `StatWatcher` polls `statSync` on a `setInterval` (default 5007 ms),
  remembers `{mtimeMs, size}` and calls the listener when either changes.
  The timer is `unref`'d so a watcher alone does not hold the process open.
- `fs.unwatchFile` is a stub over a path→watcher map that closes matches.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | the prelude was patched but not rebuilt, so `Dir.readSync` appeared missing | `fs.opendirSync(...).readSync()` | rebuild before testing |
| 2 | medium | `statSync` raw objects expose `isDirectory` as a boolean, not a method | `entry.isDirectory()` | raw flag used, not called |
| 3 | medium | an interval keeps the loop alive forever | script with only a watcher | `unref()` when available |
| 4 | low | eager listing means entries created after `opendir` are invisible | long-lived Dir | documented; a real handle needs `fdopendir` |
| 5 | low | `unwatchFile` ignores the listener argument and closes all watchers for a path | design | documented |

async `opendir` returns a Dir, and `watchFile` reports a size change from 1 to
