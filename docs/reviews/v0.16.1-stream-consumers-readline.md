# v0.16.1 — stream/consumers and readline/promises

## Implemented

- `stream/consumers` builtin: `buffer`, `text`, `json`, `arrayBuffer`, `blob`.
- `readline/promises` builtin: `createInterface` returns the existing interface
  with a Promise-returning `question()` and an async iterator over lines.
- CJS/ESM wiring for both subpath builtins.

## Application review

| # | Severity | Finding | Verification |
|---|---|---|---|
| 1 | high | libraries importing `stream/consumers` failed at resolve time | text/json/buffer tests consume real `PassThrough` streams |
| 2 | high | `readline/promises` did not exist | `question()` resolves `answer` from a piped line |
| 3 | medium | consuming an ended stream could hang | listeners attach before end in the test; end resolves the buffer |
| 4 | low | prompt output is only written when an output stream is supplied | documented; matches the base readline implementation |

## Verification

`tests/js/stream_consumers_readline.js`:
`text hello`, `json 1`, `buffer 3`, `readline answer`. Full gate 14/14.

## Residual

- `consumers.blob` requires the global `Blob` (present since v0.12.x).
- No `maxBuffer` option; consumers buffer the whole stream.
- `readline/promises` async iterator shares buffering with `question()`, so
  mixing both styles on one interface can drop a line; documented, not fixed.
- No `readline.Interface` class export (only the factory).
