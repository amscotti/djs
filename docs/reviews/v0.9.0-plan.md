# v0.9.0 plan review

Scope audited against `docs/ROADMAP.md` and the promises made when TLS was
deferred in v0.7.

## Findings

1. **TLS has no home (blocking for v1.0).** v0.7's COMPAT text deferred
   `tls`/`https` to "the crypto phase", and the roadmap table still says
   `tls | absent | v0.9.0`, but the v0.9.0 phase row only lists
   `crypto`/`zlib`. Without TLS, `https` and `fetch(https://)` cannot exist,
   and the v0.10.0 HTTP server cannot be exercised over TLS.
   **Disposition:** insert **v0.9.1 — TLS client and HTTPS transport** between
   v0.9.0 and v0.10.0. It is scheduled separately so the crypto/zlib gate can
   land and be reviewed without a half-finished TLS state machine in the same
   change.
2. **`net.Server` is a hidden dependency.** The v0.10.0 row says "HTTP server"
   but not `net.Server`, while the roadmap says no `net.Server` before
   v0.10.0. The HTTP server needs a listening socket abstraction anyway.
   **Disposition:** add `net.Server`/`net.createServer` to v0.10.0 explicitly;
   it is the transport under `http.Server`.
3. **New network surfaces need a permission story.** `listen` accepts
   connections and `dgram.send` emits packets to arbitrary hosts; the v0.4
   permission matrix only covers outbound `net.connect`. Accepting a
   connection from any peer is a different capability from connecting out.
   **Disposition:** v0.10.0 adds `--allow-listen=host:port` (default deny) and
   gates `dgram.send`/`bind` on the existing `net` rule with `host:port`.
4. **`timingSafeEqual` is missing from the crypto row.** Auth code and token
   comparison use it; without it callers write timing-unsafe comparisons.
   **Disposition:** added in v0.9.0.
5. **`crc32` is absent.** Low value for the runtime's use cases; documented in
   COMPAT instead of implemented.
6. **`worker_threads` has only a "decision" exit criterion.** Acceptable, but
   the decision must be an ADR with memory/isolation numbers, not a sentence.
   **Disposition:** v0.10.0 writes `docs/adr/0002-worker-threads.md` with the
   measured cost of a second QuickJS runtime and the chosen deferral.
7. **v1.0 portability is under-planned.** The v1.0 row promises macOS/Windows,
   but v0.9.0 links `libcrypto.so.3` by soname and every networking module is
   POSIX-`poll` based. **Disposition:** v1.0 must start with a portability ADR;
   do not tag v1.0 until the OpenSSL/zlib/socket seams are abstracted. This is
   recorded as a v1.0 entry criterion, not moved earlier.

## Exit criteria added

- v0.9.0: known-answer vectors for every digest, binary (non-UTF-8) inputs,
  HMAC, CSPRNG, gzip/deflate round-trips, streaming round-trip, truncated
  input error, sanitizer clean.
- v0.9.1: TLS handshake against a local OpenSSL server, certificate
  verification failure is an error (not a silent success), HTTPS GET through
  the existing HTTP client, loopback only.
- v0.10.0: server conformance subset (routing, headers, chunked response,
  body limits), `dgram` loopback, `readline` line splitting, permission
  denial for listen/send.
