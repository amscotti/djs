# v0.13.1 — HTTP/2 (h2c)

## Plan

Deliver HTTP/2 client and server for cleartext h2c (prior knowledge). TLS/ALPN
is out of scope until the TLS layer exposes ALPN; `worker_threads` moves to
v0.13.2. This closes the version range the user asked for (v0.13.1) with one
deferred row beyond it.

## Architecture

- **Frames**: 9-byte header, DATA/HEADERS/SETTINGS/PING/GOAWAY/RST_STREAM,
  SETTINGS ACK, PING ACK, padding/priority flags parsed, stream-id masking.
- **HPACK**: static 61-entry table, integer/string codecs, indexed, literal
  (with and without indexing), never-indexed and dynamic table size updates.
  The dynamic table evicts by RFC size accounting (name+value+32).
- **Huffman**: the full 257-symbol code table from RFC 7541 Appendix B is
  embedded and decoded bit-by-bit through per-length maps, so Node/nghttp2
  header blocks decode correctly. Encoding intentionally stays raw (no Huffman).
- **Client**: queued frames until TCP connect, preface + SETTINGS, per-stream
  HEADERS and DATA, response/data/end events.
- **Server**: preface validation (one-shot), SETTINGS exchange, stream events
  with `respond`/`write`/`end`.
- **Flow control**: ignored (WINDOW_UPDATE is a no-op, initial 65535 window is
  enough for the tested payloads).

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | writing the preface immediately after `net.connect` threw `ERR_SOCKET_CLOSED` (no fd yet) | `http2.connect(...).request(...)` | preface sent in the `connect` listener; requests queue until then |
| 2 | high | preface stripping ran on every chunk; the second chunk (SETTINGS+HEADERS) was compared as a preface and the socket destroyed | first request hung | `_prefaceDone` one-shot flag |
| 3 | high | HPACK Huffman strings from Node could not be decoded → all Node interop failed | Node server → djs client | RFC table embedded; per-length decode maps |
| 4 | medium | request HEADERS were lost because `socket.write` bypassed the queue flush path | request never reached the server | `_send` queue used by streams and sessions |
| 5 | low | no CONTINUATION reassembly; large header blocks fail | >16 KiB headers | documented |
| 6 | low | no flow-control accounting | large responses | documented; initial window suffices for tests |

## Verification

- `tests/js/http2.js` + golden: own client/server, `server-stream GET /x`,
  `200 text/plain`, body `hello`, clean exit (gate-safe).
- **Node interop both directions** (manual, Node v26):
  - djs client → `node http2.createServer` → `status 200`, `body from-node`
    (proves Huffman decode and our HEADERS encoding are accepted)
  - `node http2.connect` → djs server → `status 200`, `body from-djs`
    (proves our response headers/flow accepted by nghttp2)

Full gate 12/12 (sanitize includes `http2`).

## Residual

TLS/ALPN (wss/h2 over TLS), flow control, server push, trailers, priority,
CONTINUATION reassembly, h2c upgrade from HTTP/1.1, and Huffman encoding.
`worker_threads` is v0.13.2.
