# v0.13.7 — crypto, HTTP upgrade, Blob/FormData

## Plan

Close the crypto gaps that matter to auth and transport libraries: async
`hkdf`, key generation, streaming `createSign`/`createVerify`, exportable
`KeyObject`s, and `X509Certificate` inspection. WebCrypto `subtle` is the next
release and builds on this key material.

## Architecture

Blob/File are JS classes over Buffers with `text`/`arrayBuffer`/`stream`/
`slice`; FormData stores string or Blob entries and `fetch` encodes multipart
with a random boundary.

HTTP: the server parser now detects `Connection: upgrade` plus an `Upgrade`
header, stops the HTTP state machine, passes the socket and any post-header
bytes (`head`) to an `upgrade` listener, and destroys the socket if nobody
listens.

Crypto — native (`src/djs/apis/crypto.d`):

- `generateKeyPair(type, bits, curve)`:
  - RSA via `RSA_generate_key_ex` with e=65537, assigned to an `EVP_PKEY`;
  - EC via `EC_KEY_new_by_curve_name` (P-256/384/521) + `EC_KEY_generate_key`;
  - Ed25519 via `EVP_PKEY_CTX_new_from_name("ED25519")` + keygen.
  Private and public keys are exported as PEM through memory BIOs.
- `x509(pem)` parses with `PEM_read_bio_X509` and returns subject, issuer,
  validFrom/validTo (ASN1_TIME_print), SHA-256 fingerprint, serial.
- `x509CheckHost(pem, host)` uses `X509_check_host`.

Prelude:

- `crypto.hkdf(...)` (async wrapper over `hkdfSync`), `createSign`/
  `createVerify` buffer `update()` chunks and sign/verify once;
- `generateKeyPairSync`/`generateKeyPair` return `KeyObject`s;
- `KeyObject.export({format:"pem"})` returns the stored PEM, `der` returns the
  base64 body decoded as DER;
- `X509Certificate` exposes subject/issuer/dates/fingerprint/serial and
  `checkHost`.

`createDiffieHellman`, no custom RSA public exponent, no encrypted key export.
