## Work that was inserted during reviews

- **v0.9.1 TLS client**: v0.7 deferred TLS to the crypto phase, but v0.9.0's
  row never scheduled it. Delivered before the server phase so `https` and
  `fetch(https://)` are real rather than stubs.
- **`net.Server`**: implicit in "HTTP server" but listed only in the roadmap.
  Added to v0.10.0.
- **`--allow-listen`**: inbound connections are a separate capability from
  outbound `net.connect`; added with tests.
- **Generation-tagged socket ids**: pre-existing net weakness made worse by
  accepted sockets; fixed in v0.10.0.

## Explicitly post-1.0 (do not block the tag)

1. **HTTPS server**: needs `cert`/`key`/`ca`, ALPN, TLS server state. Planned
   v0.10.0 review records it; not part of the HTTP server subset.
2. **`worker_threads`**: ADR 0002 defers it; use child processes.
3. **HTTP keep-alive, chunked request bodies, WebSocket upgrade, HTTP/2.**
4. **Server-side request deadlines / graceful drain.** Slowloris is bounded
   only by the 128-socket table.
5. **`crypto` breadth**: ciphers, KDFs, sign/verify, WebCrypto, `crc32`.
6. **TLS breadth**: client certificates, custom trust store, ALPN, session
   resumption.

## What v1.0.0 must not forget

- **Portability ADR first.** `libcrypto.so.3`/`libssl.so.3` are linked by
  soname and every socket path is POSIX `poll`. macOS needs a different link
  strategy; Windows needs winsock/`WSAPoll` or libuv handles. Do not tag v1.0
  before the platform seams are abstracted and the same gates run on macOS.
- **Version discipline**: `VERSION`, `djsVersion` and `scripts/check-version.sh` are now a gate; bump them in the same commit as the tag.
- **Packaging** must declare the OpenSSL/zlib runtime dependencies and ship
  `THIRD_PARTY.md`; `scripts/package.sh` already produces the tarball and
  sha256.
- **ABI policy**: the QuickJS pin and the `scripts/check-abi.sh` assertions
  stay authoritative; an embedding header must not expose internal structs.
- **Source maps / diagnostics** for stack traces.
- **Hardening pass**: per-connection deadlines, output budgets, and a re-run
  of the soak/alloc gates on each platform.
