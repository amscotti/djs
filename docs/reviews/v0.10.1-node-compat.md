# v0.10.1 — Node compatibility kernel and Express target

## Why this phase exists

The v0.10.0 plan review pushed HTTPS server, HTTP hardening, crypto breadth,
HTTP/2, WebSocket and `worker_threads` past 1.0.0. That was too conservative:
the runtime's value is running real Node packages, and the fastest way to find
the missing surface is to run one. **Express 4** was chosen as the first
framework target because it exercises module loading, `http`, `stream`, `fs`
(static files), `events`, `util`, `path`, `querystring` and error handling at
once, without native addons. This phase is the compatibility work needed to
make it run unmodified; the remaining deferred items are now scheduled in
v0.11.0–v0.13.1 (see `docs/PLAN.md`).

## Architecture

- **Stack introspection lives in the prelude.** QuickJS exposes `Error.stack`
  as a string and its `stack` accessor rejects non-strings, while V8 packages
  (`depd`, `debug`) require `Error.captureStackTrace` + `Error.prepareStackTrace`
  to yield CallSite objects. The prelude temporarily disables
  `prepareStackTrace`, parses the raw frames, builds CallSite objects and
  installs the result with `Object.defineProperty` so it shadows QuickJS's
  accessor. Scope: parsing assumes the QuickJS frame format
  (`at fn (file:line:col)`); it does not implement `CallSite` methods that
  V8-only code might use beyond the common accessors.
- **`require('stream')` is the constructor**, not a namespace object. The
  concrete classes hang off it, matching Node; this fixed `send`'s
  `util.inherits(SendStream, Stream)`.
- **`EventEmitter` initialises lazily.** Express mixes the prototype into an
  object without calling the constructor; `_add`/`emit` now create `_events`
  on demand (and tolerate its absence on reads).
- **fs stream classes are real constructors.** `createReadStream` returns a
  `ReadStream` instance backed by a whole-file `readFile`; `WriteStream`
  buffers and writes on final. They are not chunked I/O, but `instanceof`
  works and small static files stream through `send`.
- **Main-module paths are set at entry.** Script entries are not wrapped by
  the CommonJS loader, so `main.d` installs `__dirname`/`__filename` globals
  before evaluation.
- **Small builtins**: `tty.isatty`, legacy `querystring`, and
  `string_decoder.StringDecoder` with manual UTF-8 boundary buffering
  (QuickJS's `TextDecoder` ignores `{stream:true}` — verified by the `é`
  split test).
- **`Buffer.allocUnsafeSlow`/`compare`** exist so `safe-buffer` takes its fast
  path and exports the real Buffer instead of its polyfill (which lacked
  `isBuffer`/`byteLength`).

## Verification

- `scripts/gate-express.sh`: installs Express (skips offline), starts
  `examples/express-app` under `djs`, asserts static `/`, JSON `/api/items`,
  route param `/api/user/42`, POST JSON echo and a 404 — **5/5**.
- `tests/js/node_compat.js` + golden: stream export, EventEmitter mixin,
  CallSite array, main-module paths, Buffer statics, querystring, UTF-8
  boundary decoding, fs stream `instanceof`.
- Full gate: 12 steps (integration 98, sanitize 61, permissions 42, diff 11,
  express 5 checks).
- ASan/LSan clean on `node_compat`.

## Residual

- Express 5, Fastify, Koa, Socket.IO and native-addon frameworks are untested;
  WebSocket/upgrade and N-API remain the blockers listed in
  `docs/COMPARISON.md`.
- `StringDecoder` does not strip a UTF-8 BOM; non-UTF-8 encodings are not
  boundary-safe.
- `Error.stackTraceLimit` is only consulted by our parser implicitly (frame
  count is whatever QuickJS produced), not used to truncate.
