# v0.14.2 — architectural cleanup

Scope: the cleanup findings from `tier1-architecture-review.md`, with the
prelude split deliberately deferred (too large to mix into a behavioural
release).

## Changes

| Finding | Change |
|---|---|
| CJS entry scripts ran as global scripts, leaking top-level `var` | every CommonJS entry now goes through `cjsLoad`'s module wrapper; `module`/`exports`/`require`/`__filename`/`__dirname` are wrapper arguments |
| shebang lines were not stripped | `cjsLoad` skips `#!…` before wrapping (both entries and required modules) |
| upgraded connections stayed in `server._connections` | removed from tracking and header timeout cleared at handoff, so `server.close()` no longer waits on a socket owned by `ws` |
| `Readable.toWeb` enqueued without backpressure | pauses the source when `desiredSize <= 0`, resumes in `pull` |
| duplicate `wsFind`/`wsU16`/`wsW16`/`wsU32` byte helpers | replaced with Buffer `indexOf`/`readUInt16BE`/`writeUInt16BE`/`readUInt32BE` |
| `async_hooks` availability implied | documented as an engine-level limitation and removed from the roadmap |

## Application review

| # | Severity | Finding | Verification |
|---|---|---|---|
| 1 | high | entry wrapper changes scope/args | `entry_scope` golden: no global leak, module/require present, absolute paths |
| 2 | medium | `server.close()` with a live upgraded socket | `upgrade_close` golden: callback fires while the socket is still open |
| 3 | medium | `toWeb` pause/resume re-entrancy | existing `stream_web_interop` + `ws` compat pass |
| 4 | low | Buffer method replacement changed byte semantics | `websocket`, `http2`, `ws` compat goldens pass |
