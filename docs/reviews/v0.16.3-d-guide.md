# v0.16.3 — D-guide conformance and final review

Scope: the D-craft pass over the tree (slices, `@safe`/`@trusted`, tables over chains,
`scope(exit)`), plus a close-out review of the changes since v0.16.2. Every finding below has a
disposition; nothing is "noted" without one.

Gate at close: **14/14**, integration **161/161**, `dub test` **10 modules / 12 blocks**.

## Findings

| ID | Finding | Disposition |
|---|---|---|
| R-01 | `cjsnames` de-duplicated export names with a linear scan per name: 1.2 s at 25k exports, 5.1 s at 50k, 94.4 s at 200k. | **Fixed.** FNV-1a open-addressed index (≤50% load, hash stored in the slot). Scanning is now linear: ≈7–10 ms at 25k, ≈15–17 ms at 50k, ≈95 ms at 200k on this noisy 2-core host (best of three: 7.0 / 15.2 / 94.7). End-to-end CJS→ESM for a 50k-export module: 10.65 s → 5.4 s. |
| R-02 | Quoted keys were never collected: `module.exports = { "e": 4 }` produced no `e` export, because the string skip ran before the key branch. | **Fixed.** Position decides key vs value (`atPropertyStart`); pinned by a unittest that fails without the fix. |
| R-03 | `isRelativeSpec(".")` and `safeRelativeTarget(".")` read `s[1]`/`s[2]` past the NUL terminator. | **Fixed.** Both are slice cores now; `isRelativeSpec` was also renamed `isPathLike`, since it returns true for `/abs` as well as `./x`. |
| R-04 | `JSON.parse` accepted a valid prefix and ignored trailing garbage. | **Fixed.** Non-whitespace after the root value is a parse error, matching Node. |
| R-05 | `builtinAlias` was an 87-entry `strcmp` chain, so a duplicated alias was a silent first-match. | **Fixed.** One string `switch`: a duplicate case label is a compile error. |
| R-06 | `esm.d` carried two parallel 43-branch chains (export names, `__m` binding) that could drift. | **Fixed.** One `builtinFacades` table of `{spec, exports, binding}`; a `static assert` rejects duplicate specifiers. Equivalence with the v0.16.2 chains was checked mechanically (43/43 bindings and 43/43 export arrays identical, plus `djs:process` on the old default and `djs:ws` with no exports). |
| R-07 | The synchronous fs entry points freed `w.path`/`w.data` on every error branch (34 `free(w.path)` sites, duplicated in `fsAfterCb`). | **Fixed** for the 12 sites where the function owns the buffers (`scope(exit)`, one release point). The 20 remaining sites are in `startFsWork`, where ownership is handed to libuv — converting them would hide the handoff, so they stay explicit (**deferred**, reason recorded here). |
| R-08 | Zero `@safe` in 16.8k lines, so `-release` ran with no bounds checks outside the standard library. | **Partly fixed.** 37 `@safe` / 27 `@trusted` / 24 `pure`; tokenizer, path predicates and export-target checks are `@safe` cores behind named `@trusted` edges. The rest of `apis/` is a descriptor- and `JSValue`-moving layer; converting it needs request-struct restructuring (**deferred**, recipe in D-GUIDE §4 and `jsReadFileSyncImpl` as the worked example). |
| R-09 | `dfmt` is named in the guide as optional tooling but was never evaluated. | **Rejected.** dfmt 0.15.2 rewrites `scope(exit)` as `scope (exit)` and joins wrapped parameter lists — ~140 changed lines in `path.d` alone, no correctness gain. Recorded in D-GUIDE §8 so it is not re-litigated. |
| R-10 | `integration.sh` hardcoded the expected `--version` (`v0.16.2`), so a version bump failed three tests. | **Fixed.** The check reads `VERSION`; the two goldens were updated. |
| R-11 | `BENCHMARKS.md` claimed startup parity with Node and a "Node startup ~5× higher" trade-off. | **Fixed.** Re-measured on Node 26.7: Node 38.7 ms, djs 45.5 ms (1.17×), and the CPU-loop bullet now computes the engine-only delta from the run instead of hardcoding it. |
