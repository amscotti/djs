# v0.14.4 — stream state and module diagnostics

## Changes

- `Readable` owns `_readableState` (`endEmitted`, `objectMode`, and a computed
  `length`) instead of `Socket` patching it in. Socket and every other Readable
  now expose the same shape `ws` and stream consumers inspect.
- `Socket` no longer overrides `_readableState`/`_writableState`; both come from
  the stream base classes.
- Module errors now include the specifier in `message`
  (`cannot find module './x'`), matching the `path` property Node sets.

## Application review

| # | Severity | Finding | Verification |
|---|---|---|---|
| 1 | medium | state shim lived only on Socket, so other Duplex consumers saw no `_readableState` | `ws` compat + `stream_web_interop` |
| 2 | medium | `_readableState.length` always 0 | computed from buffered chunks; ws close path no longer short-circuits |
| 3 | low | module message lacked the specifier | `require("./definitely-missing")` prints `cannot find module './definitely-missing'` |

## Verification

- full gate 14/14
- `ws` echo, `jose` HS256/RS256, `stream_web_interop`, `module_resolve`

## Residual

Still not a fully conformant Node Duplex: `cork` is a no-op, pause/resume is
queue-based rather than high-water-mark based, and `_writableState` is a small
subset. Enough for `ws` and ordinary HTTP, not for every stream consumer.
