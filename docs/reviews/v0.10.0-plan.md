# v0.10.0 plan review

## Findings

1. **`net.Server` was implicit.** The phase row said "HTTP server" while the
   roadmap deferred `net.Server` to the same version. Both are required; the
   server is the transport under `http.Server`. Added to the scope explicitly.
2. **Inbound connections had no permission.** `--allow-listen=host:port` is
   now a separate capability (default deny). Accepting any peer is not the
   same grant as connecting out; `dgram.bind`/`send` stay on `net` with
   `host:port`. Verified by `gate-permissions.sh`.
3. **Worker evaluation needed a real decision record.** Replaced the vague
   "decision or deferral" exit criterion with ADR 0002, including measured
   baseline RSS (10.5 MiB), the absence of `SharedArrayBuffer`, and the
   per-runtime ownership problem for every global table. `Worker` throws
   `ERR_WORKER_THREADS_UNSUPPORTED`.
4. **HTTPS server is unscheduled.** Serving TLS needs `cert`/`key`/`ca`
   options, ALPN and a TLS server path. It is not part of v0.10.0 and is
   recorded as an explicit post-1.0 item (with client certificates) rather
   than silently implying parity with `https.createServer`.
5. **HTTP server limits must be named.** Keep-alive, chunked request bodies,
   `Expect: 100-continue`, trailers and WebSocket upgrade are out; 16 KiB
   headers, 8 MiB bodies. COMPAT lists them.
6. **No server-side request timeout.** A slowloris client can hold one of the
   128 socket slots indefinitely. Accepted as a documented residual; a
   deadline belongs with the v1.0 hardening pass, not this phase.
7. **`readline` is basic.** No history/editing/raw mode; documented. The REPL
   keeps its own loop.

## Exit criteria

- HTTP GET/POST/404 through the real client, headers and status preserved.
- Raw `net.Server` echo with clean close.
- UDP loopback ping/pong with address/port reported.
- `readline` over piped stdin, LF and CRLF.
- `listen` and `dgram.bind` denied without grants; allowed with them.
- Worker stub test plus ADR 0002.
- Full gate (including sanitizer and soak) green.
