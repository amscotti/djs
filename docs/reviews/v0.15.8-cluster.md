# v0.15.8 — cluster over fork IPC and process.pid

## Implemented

- `process.pid` (native `getpid`) — required by cluster-aware apps and logging.
- Native `listen` accepts a `reusePort` flag (`SO_REUSEPORT`).
- Cluster workers set `reusePort` automatically for `Server.listen`, so each
  worker binds the same port and the kernel balances connections.
- `cluster` builtin:
  - `isPrimary`/`isMaster`, `isWorker`, `workers`, `settings`
  - `fork(env)` spawns the current entry with `DJS_CLUSTER_WORKER`/`ID`
  - worker objects expose `id`, `process`, `send`, `kill`, `disconnect`, and
    `message`/`exit` events
  - primary emits `fork`, `online`, `exit`; `disconnect(cb)` waits for exits
  - `cluster.worker` in the child with `send`/`disconnect`/`kill`

## Application review

| # | Severity | Finding | Verification |
|---|---|---|---|
| 1 | high | no way to run one listener per worker | two workers bind the same port with `SO_REUSEPORT`; four requests all answer |
| 2 | high | `process.pid` was undefined | prints a real pid; master chooses its port from it |
| 3 | high | workers were denied `--allow-listen` | fork grants `--allow-listen`; workers report ready |
| 4 | medium | cluster API surface was missing entirely | `cluster_basic` exercises fork, messages, workers, kill |
| 5 | low | load balancing is kernel-driven | documented: no round-robin scheduling or shared-handle handoff |

## Verification

`tests/js/cluster_basic.js` golden: four `response ok`, `workers 2`. Full gate
14/14.

## Residual

- No shared-listener handle passing: balancing is `SO_REUSEPORT`, not Node's
  round-robin scheduler; `cluster.schedulingPolicy` is not implemented.
- No graceful reload, `worker.online` timing guarantees, `setupPrimary`, or
  `cluster.settings.exec`/`args`.
- Worker IPC still uses the loopback channel; fd-3 remains deferred.
- `process.pid` was added in this release because cluster needed it; other
  process fields (`ppid`, `title`) are still absent.
