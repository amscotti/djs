# v0.13.5 — assert, module, stream/promises

## Plan

Close the three builtins whose absence would bite test tooling and libraries,
as identified in the compatibility scorecard: `assert` (plus `assert/strict`),
`module`, `stream/promises`. They are implemented in the prelude on top of the
existing runtime, wired through the classifier for both CJS and ESM.

## Architecture

- `assert`: `AssertionError` (code `ERR_ASSERTION`, `actual`/`expected`/
  `operator`), `ok`, `equal`/`notEqual`, `strictEqual`/`notStrictEqual`,
  `deepEqual`/`deepStrictEqual` (and negations), `throws`/`doesNotThrow`,
  `rejects`/`doesNotReject`, `fail`, `ifError`, `match`/`doesNotMatch`.
  `deepStrictEqual` compares prototypes, own enumerable keys (including
  symbols), Date/RegExp/Error, Map/Set, Buffer/TypedArray/ArrayBuffer, and
  handles cycles with a pair memo.
- `assert/strict`: a callable with the same methods mapped to strict variants;
  `assert.strict` points at it.
- `module`: `Module` class (data holder), `createRequire(filename | file URL)`
  built on the runtime's `__djs.requireFrom`, `isBuiltin`, `builtinModules`,
  `syncBuiltinESMExports` no-op.
- `stream/promises`: `pipeline` and `finished` wrap the existing callback
  implementations in promises.
- ESM facades now map every builtin (previously several fell through to
  `globalThis.process`) and export named symbols for the new modules.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | `assert`/`module`/`stream/promises` were absent | scorecard | implemented |
| 2 | high | ESM builtin facades fell through to `globalThis.process` for vm, http2, tty, querystring and others | `import vm from "node:vm"` returned process | explicit mapping for all builtins |
| 3 | medium | `createRequire` initially used `g.requireFrom`, but the native lives on `__djs` | `TypeError: not a function` | use `__djs.requireFrom` |
| 4 | medium | relative JSON require (`require("./package.json")`) fails even in the repo root — found while testing createRequire | `cannot find module` | out of scope; recorded, test uses a JS fixture |
| 5 | low | `doesNotThrow`/`doesNotReject` treat a non-matching expected error as a failure instead of rethrowing | `assert.doesNotThrow(fn, TypeError)` with a RangeError | documented simplification |

## Verification

- `tests/js/assert_module.js`: 14 deterministic lines covering comparisons,
  deep equality (objects, arrays, Buffer, Map, Set, Date, RegExp, cycles),
  AssertionError fields, message propagation, throws (class, regexp,
  validator), match, strict alias, async rejects, createRequire, isBuiltin and
  builtinModules.
- `tests/js/stream_promises.js`: pipeline success (`ABC`), `finished` resolve,
  pipeline rejection (`boom`), `finished` rejection (`sink failed`).
- ESM smoke: `import assert, { strict } from "node:assert"`,
  `import { createRequire } from "node:module"`,
  `import { finished } from "node:stream/promises"` all work.
- Existing suites unaffected (gate below).

Full gate 13/13.

## Residual

`require.resolve` on createRequire is approximate; no `Module._load`
internals; `stream/promises` lacks iterable/generator pipeline inputs;
`assert` lacks `snapshot`, `partialDeepStrictEqual` and custom-message Error
objects; relative JSON require remains broken.
