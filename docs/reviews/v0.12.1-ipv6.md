# v0.12.1 — net IPv6, perf_hooks, os completeness

## Plan

IPv6 had slipped twice (v0.11.1 and v0.11.2). It is the first item here and is
now implemented for clients, listeners and `dns.lookup`, with literal `::1`
coverage. The rest of the original v0.12.1 scope (sign/verify, fs.watch,
dns.resolve, vm, WebSocket, Web Streams, fs.opendir, events extras) moves to
**v0.12.2**; trying to land all of it in one phase would have repeated the
mistake of claiming more than the gate verifies.

Also delivered: `perf_hooks.performance`, `os.constants.signals`,
`os.availableParallelism`, `os.machine`.

## Architecture

- `dns.lookup` now resolves with `AF_UNSPEC` and formats either family; the
  result's `family` is 4 or 6 instead of always 4.
- The connect path iterates both `AF_INET` and `AF_INET6` results, sets the
  port in the right sockaddr and keeps the first successful non-blocking
  connect.
- `net.listen` accepts IPv6 literals (`::1`, `::`, any address containing a
  colon), chooses `AF_INET6`, and binds with `sockaddr_in6`. `Server.address`
  reports `family: 'IPv6'` from the host string.
- `perf_hooks` reuses QuickJS's `performance.now` and adds a no-op
  `PerformanceObserver` shape for libraries that only construct one.
- `os.constants` is a small signal table (Linux numbers); `os.machine` maps
  `x64` to `x86_64`; `availableParallelism` counts `cpus()`.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | DNS hints were pinned to `AF_INET`, so `::1` never resolved | `dns.lookup("::1")` | `AF_UNSPEC` + both-family formatting |
| 2 | high | connect only accepted `ai_family == 2` | IPv6 client | accept 10/2 and set `sin6_port` |
| 3 | high | listener rejected anything containing `:` | `listen(0,"::1")` | IPv6 bind branch + `sockaddr_in6` |
| 4 | medium | `Server.address().family` was hardcoded IPv4 | IPv6 listener | derived from `_host` |
| 5 | low | `perf_hooks` was not in the builtin table | `require("perf_hooks")` | classify + CJS entries |
| 6 | medium | AF_UNSPEC made `dns.lookup("localhost")` return `::1` and broke the deterministic net gate (expected 127.0.0.1/4) | `scripts/gate-net.sh` | lookup prefers an IPv4 answer, then falls back to IPv6; connect still uses getaddrinfo order |
| 6 | low | `os.constants`/`machine`/`availableParallelism` absent | feature probes | added in the JS facade |

## Verification

- `tests/js/net_ipv6.js` + golden: `dns.lookup("::1")` → `::1`/6; listener on
  `::1` reports `family: IPv6`; client connects and echoes `v6:hi`.
- `node_partials` extended with `perf_hooks` and `os.constants` assertions.
- Full gate 12/12.

## Residual

Everything moved to v0.12.2, plus: no IPv6 DNS AAAA preference logic beyond
getaddrinfo ordering, no dual-stack wildcard (`::` binds v6-only on Linux
unless `IPV6_V6ONLY` is cleared), and listener `address()` reports the literal
host rather than the bound wildcard.
