# v0.11.2 — HTTPS server

## Plan

Batch 3 of the pre-1.0 schedule: make the TLS layer usable as a server so
`https.createServer` stops throwing `ERR_TLS_SERVER_UNSUPPORTED`.

Delivered: `tls.createServer(options, listener)`, `tls.Server`,
`https.createServer({cert, key}, handler)` and `https.Server`. Certificates and
keys are PEM **file paths**, matching the native loader.

Not delivered, and explicitly moved to **v0.12.1**: net IPv6. `net.d` hardcodes
`AF_INET` in DNS hints, connect, bind and `getsockname`; it is an address-family
refactor across four call sites and did not belong in a TLS release. This is the
second time IPv6 has moved, so it is now the first item of v0.12.1 rather than a
"maybe".

Also deferred: client certificates, custom CA on the server, ALPN, certificate
reload. The client still uses the system store and `rejectUnauthorized`.

## Architecture

- The server reuses the client's `TlsSock` table, `SSL_read`/`SSL_write` poll
  path and slot lifecycle, so there is one TLS read/write implementation.
- `net.detachFd(id)` stops and frees a socket's libuv poll handle, releases its
  callbacks and returns the descriptor without closing it. TLS then owns the fd;
  this is the hand-off boundary between `net` and `tls`.
- `tls.acceptFd(fd, cert, key)` builds a server `SSL_CTX`, loads the PEM
  cert/key, verifies the keypair, performs `SSL_accept` with a 10 s poll
  timeout, restores non-blocking mode and registers a poll handle.
- `TlsServer` implements `listen`/`address`/`close` over `__djs.net.listen`
  directly. On accept it detaches the fd, wraps it, emits `secureConnection`
  then `connection`, and starts reading.
- `HttpServer` chooses its transport from the options: `cert`/`key` selects
  `TlsServer`, otherwise the plain `net.Server`. The HTTP/1.1 state machine,
  keep-alive, chunked bodies and deadlines are shared unchanged.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | `net.detachFd` was implemented but never added to the install table, so `__djs.net.detachFd` was `undefined` | `typeof __djs.net.detachFd` | registered in `installNet` |
| 2 | high | `acceptFd` received the net **socket id** where it expected a **fd**; `SSL_set_fd(1)` talked to stdout | `https.createServer(...).listen(...)` never accepted | JS detaches first, then passes the fd |
| 3 | high | server-side `TlsSock` never created or started a `uv_poll` handle, so `SSL_read` was never called and requests never arrived | TLS client connected, server saw no data | poll init/start added to `acceptFd` |
| 4 | medium | `acceptFd` returned an `Error` object as a normal value, so a bad cert path produced a silent no-response instead of an error event | wrong cert path | `TlsServer` checks the result type and emits `tlsClientError`; test path fixed |
| 5 | medium | the test fixture path was `tests/js/fixtures/tls` instead of `tests/fixtures/tls` | `https_server.js` hung | path corrected |
| 6 | low | handshake blocks the event loop (accepted design for now) | slow TLS client stalls other connections | documented; worker-thread accept is future work |
| 7 | low | `TlsServer.close()` does not track live TLS sockets, so `close` callbacks can fire before sockets finish | close during a request | documented; HTTP server's own connection set drains first |
