# v0.10.0 architecture review

## Shape

- **Listener in `net.d`.** `net.listen` creates an IPv4 non-blocking socket
  (`SO_REUSEADDR`), binds/listens and polls with `uv_poll`. `accept4` uses
  `SOCK_NONBLOCK|SOCK_CLOEXEC`; each accepted fd is registered in the existing
  `NetSock` table so `startRead`/`write`/`end`/`close` work unchanged.
- **Generation-tagged socket ids.** Socket ids were slot indexes; a stale
  client handle could read from or write to a later accepted connection in the
  same slot. Ids are now monotonic per socket and resolved by `findSock`.
- **Listener teardown uses `CloseCtx`.** The first cut handed a `Listener*` to
  `pollCloseCb`, which casts its data to `CloseCtx` and frees it — an invalid
  free of static memory after `server.close()`. A dedicated close path passes
  a heap `CloseCtx` and lets the existing callback close the fd.
- **HTTP is a JS state machine.** Request parsing (header block, content-length
  body, 16 KiB/8 MiB caps), `IncomingMessage`/`ServerResponse`, chunked
  responses and connection close live in the prelude. The native layer only
  moves bytes. This keeps policy and Node-shaped semantics out of D.
- **`dgram` is its own table.** UDP sockets are polled with `recvfrom` into a
  64 KiB buffer; `rinfo` is built natively. No multicast/broadcast options.
- **`readline` is pure JS** over `process.stdin`, so it inherits the lazy
  stdin polling and works in files as well as the REPL (which does not use it).

## Findings and dispositions

| Severity | Finding | Disposition |
|---|---|---|
| critical | listener close freed a static `Listener` through `pollCloseCb` | dedicated `closeListenerHandle` with a heap `CloseCtx` |
| high | stale socket ids could address a reused slot (client vs accepted server sockets) | monotonic ids + `findSock`; the client tests still pass |
| high | HTTP client half-closed after writing, so a same-process server saw EOF and discarded its response (`malformed HTTP response`) | client writes without `end()`; `Connection: close` ends the exchange |
| medium | passing a handler to `createServer` **and** consuming `request` events dispatched twice | handlers are registered as listeners; `_accept` only emits |
| medium | `dgram.send(..., 'localhost')` failed (`inet_pton` is literal-only) | map `localhost` to `127.0.0.1` in the JS wrapper |
| low | `http.Server` has no keep-alive; every response closes | documented; keep-alive needs a connection state machine |
| low | slowloris has no deadline | documented residual; 128-socket cap |

## Invariants

- Every accepted socket goes through `NetSock` teardown; listener teardown
  releases its callback slot and fd exactly once.
- The native HTTP layer never parses; the JS layer never touches fds.
- No new global table is unowned: `dgram` records `Runtime*` and closes only
  its own sockets at teardown.
