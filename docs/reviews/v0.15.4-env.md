# v0.15.4 — spawn environment and fork transport cleanup

## Implemented

- Async `spawn`/`fork` now honour `options.env`.
  - The JS layer converts the object to `KEY=VALUE` entries (no reflection in
    the native layer).
  - Native `child.d` builds `envp` and uses `execvpe` instead of `execvp`.
  - With no `env`, the child still inherits the parent environment.
- `fork` now passes `DJS_IPC_PORT`/`DJS_IPC_TOKEN` through the environment
  instead of an argv flag; the argv fallback remains for compatibility.
- `fork` children receive `--allow-env` alongside `--allow-net` so the IPC
  variables and ordinary configuration are readable.

## Application review

| # | Severity | Finding | Verification |
|---|---|---|---|
| 1 | high | `spawn(..., {env})` silently used the parent environment | child prints `FOO=bar` and a supplied `PATH` |
| 2 | high | fork discovered IPC through a visible argv flag | port/token now travel in the environment |
| 3 | medium | env entries leaked on early spawn errors | array freed on every post-parse error path; ASan gate |
| 4 | medium | `execvpe` ABI needed a const cast for `environ` | compiles; spawn and fork both exercised |
| 5 | medium | fork children could not read their own config env | `--allow-env` added; `fork_ipc` still passes |

## Verification

`tests/js/child_env.js` and `fork_ipc` goldens; full gate 14/14.

## Residual

- fd-3 IPC was **not** implemented. The native layer still lacks a way to wrap
  an inherited descriptor in a libuv pipe, so fork keeps the loopback socket.
  This is the next architecture item, not a hidden success.
- `fork` unconditionally grants `--allow-net`/`--allow-env`; permission
  inheritance is still a policy decision.
- No `stdio: inherit`, `detached`, or Windows environment blocks.
