# v0.14.0 — DNS record types

## Plan

`dns.resolveMx`/`resolveTxt`/`resolveSrv`/`resolveCname`/`resolveNs`/`resolvePtr`/
`resolveSoa`, `dns.resolve(host, type)`, `setServers`/`getServers`, and the
matching `dns.promises` functions. `mongodb+srv`, mail and service-discovery
clients need these; `resolve4`/`resolve6`/`lookup` stay on libc.

## Architecture

A small DNS wire client in the prelude over the existing `DgramSocket`:

- query builder for A/AAAA/MX/TXT/SRV/CNAME/NS/PTR/SOA with compression-safe
  name encoding;
- response parser with compression-pointer handling, record-type decoding, and
  a 32-hop pointer-loop guard;
- 2 s timeout, server list from `setServers` or `/etc/resolv.conf`, fallback to
  `127.0.0.1:53`, retry across servers;
- `rcode 3` maps to `ENOTFOUND`, other rcodes to `EBADRESP`, timeouts to
  `ETIMEOUT`.

A/AAAA still use `getaddrinfo`, so search domains and `/etc/hosts` keep working
for ordinary lookups.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | only A/AAAA records existed | `resolveMx` undefined | wire client |
| 2 | high | `dns.promises` had only `lookup` | `dns.promises.resolveMx` undefined | promise wrappers |
| 3 | medium | no way to point the resolver at a test server | tests needed real DNS | `setServers`/`getServers` |
| 4 | medium | `dgramModule` was not a real binding | `dgramModule is not defined` | use `DgramSocket` directly |
| 5 | low | NXDOMAIN surfaced as success | fake server returned `null` error | map rcode 3 to `ENOTFOUND` |

## Verification

`tests/js/dns_records.js` + golden, using a local UDP DNS server that returns
crafted MX, TXT, SRV, CNAME, NS, SOA and NXDOMAIN responses:

- `mx 10 mail.example.test`
- `txt v=spf1 -all`
- `srv 443 svc.example.test`
- `cname alias.example.test`
- `ns ns1.example.test`
- `soa 7 ns1.example.test`
- `promise-mx mail.example.test`
- `nxdomain ENOTFOUND`

Full gate 13/13.

## Residual

No DNSSEC, EDNS0, TCP fallback for truncated responses, CNAME chasing, search
domains for the wire client, or `reverse()` (PTR helper).
