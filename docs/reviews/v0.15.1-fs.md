# v0.15.1 — fs breadth

## Implemented

- `fs.cpSync` / `fs.cp` / `fs.promises.cp` with recursive trees, symlinks,
  `force`, `errorOnExist`, `dereference`, and parent creation
- `fs.readvSync` / `fs.writevSync` / `readv` / `writev` / promise variants,
  preserving file position across buffers
- `fs.openAsBlob(path, {type})` backed by the Blob class
- `fs.watch(path, {recursive: true})` aggregates one native watcher per
  directory and adds new subdirectories on `rename`

## Application review

| # | Severity | Finding | Verification |
|---|---|---|---|
| 1 | high | recursive copy lost nested files | `fs_cp_io` copies a two-level tree and reads both files |
| 2 | high | recursive watch silently behaved like a single-dir watch | event for `sub/c.txt` is observed after it is created |
| 3 | medium | `readv` desynchronised offsets between buffers | 1+3 byte buffers read `a` and `bcd` |
| 4 | medium | symlink copy followed the link | `lstat` branch recreates the link unless `dereference` |
| 5 | low | `openAsBlob` type lost | asserts `size 1`, `type text/plain` |

## Verification

`tests/js/fs_cp_io.js` golden; full gate 14/14.

## Residual

- `cp` does not preserve mode/timestamps, does not support filters, and is not
  atomic
- recursive watch does not remove watchers for deleted directories and may
  miss events during a rapid rename storm
- no `fs.glob`, `opendir` async iterator parity, or `statfs` breadth changes
