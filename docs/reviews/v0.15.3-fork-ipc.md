# v0.15.3 — fork IPC and process.execPath

## Implemented

- `process.execPath` (native `uv_exepath`)
- `child_process.fork(modulePath, args, options)`:
  - child gets `--allow-net` automatically
  - parent listens on an ephemeral loopback TCP port
  - child receives `--djs-ipc=<port>:<token>` as an argument and connects back
  - newline-delimited JSON both ways; first line is a token handshake
  - `child.send()`, `child.connected`, `child.disconnect()`,
    `process.send()`, `process.on('message'|'connect'|'disconnect')`
  - messages sent before the channel is ready are queued

## Why not fd 3 / env

The native async `spawn` does not yet support `options.env` or a fourth pipe.
Rather than expand the native child ABI in this release, fork uses a loopback
socket and an argv flag. This is an implementation detail; the public API
matches Node's shape. `cluster` needs handle passing and remains a separate
row.

## Application review

| # | Severity | Finding | Verification |
|---|---|---|---|
| 1 | high | fork children had no IPC at all | `fork_ipc` round-trip: `ready` → `ping` → `pong2`, exit 0 |
| 2 | high | child was denied net permission on connect | auto `--allow-net`; handshake succeeds |
| 3 | medium | sends before the channel opened were lost | queued until token handshake completes |
| 4 | medium | any local process could inject messages | random token required before messages are delivered |
| 5 | low | `process.execPath` was undefined | native `uv_exepath`; prints `/home/ubuntu/code/djs/djs` |

## Verification

`tests/js/fork_ipc.js` golden; full gate 14/14.

## Residual

- IPC is JSON-only, no advanced serialization or `MessagePort`
- no `cluster` handle sharing/SO_REUSEPORT
- `options.env` in `spawn`/`fork` is still ignored by the native layer
- loopback TCP + argv token instead of fd 3 is weaker isolation than Node
