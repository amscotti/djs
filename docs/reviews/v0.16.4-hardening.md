# v0.16.4 — pre-release hardening

A full adversarial review before making the repository public found four
critical and nine high issues across the permission model, the HTTP/TLS
layers, the fs workers and crypto. All are fixed here with regression
tests; the behaviour changes are recorded in
[`../COMPAT.md`](../COMPAT.md) under "Hardening (v0.16.4)".

## Fixed (critical)

1. **Stack buffer overflow in the audit log** (`permissions.d`): the JSONL
   writer could write up to 19 bytes past a 2048-byte stack buffer when a
   resource string (a JS-controlled path) was long. Auditing is now
   bounded, escapes control characters, opens the sink once with
   `O_NOFOLLOW|O_CLOEXEC` 0600, and aborts startup when it cannot be
   opened.
2. **TTY prompt overrode explicit denies and drops** (`permissions.d`): a
   prompt was offered whenever access was not allowed — including after an
   explicit `--deny-*` match or `process.permission.drop()`. Prompts now
   fire only when no rule matched at all; `has()` is a pure query; the
   startup `process.env` snapshot never prompts.
3. **`tls.connect`/`https` bypassed `--allow-net` entirely** (`tls.d`): no
   permission check existed on the outbound TLS path. Same host:port gate
   as `net.connect` added.
4. **Hardlink write escalation** (`fs.d`): `linkSync` checked read on the
   source and write on the destination; the shared inode made any readable
   file writable through the new path. Write is now required on both ends.

## Fixed (high)

- `SSL_VERIFY_PEER` was silently reset to `SSL_VERIFY_NONE` for connections
  without ALPN (a mis-bound `else`); the post-handshake check still
  rejected bad chains, but intended enforcement was off.
- `--allow-read=`/`-R=` (explicit empty value) silently granted the whole
  category; now a startup error.
- Cipher key/IV lengths were passed to OpenSSL unvalidated (out-of-bounds
  read inside OpenSSL with a short key); validated with
  `EVP_CIPHER_get_{key,iv}_length`.
- One malformed HPACK byte killed any `http2` endpoint (uncaught exception
  out of the socket read path); the session is destroyed instead.
- Server response headers/status were concatenated unvalidated
  (response splitting over keep-alive pipelines); the client-side
  `checkHeader` validation now applies.
- Async fs check-to-open TOCTOU: workers now verify the (device, inode)
  identity of what they open against what the permission check saw;
  a swapped leaf fails closed with `EACCES`.
- Sockets became un-closable after 128 cumulative creations (`close()`
  rejected ids above the table size while ids are monotonic).
- A write-callback that destroyed its socket crashed the poll re-arm
  (missing closing re-check after the JS call).
- `tls.acceptFd` ran an unbounded blocking handshake on the loop thread;
  now a total 10 s deadline, fd validated as a socket.

## Also fixed

Follow-up hardening driven by the first line-coverage run
(`scripts/coverage.sh`, full-suite baseline ~75%):

- `packageJsonValue` returned `main`/`type` values with JSON escapes still
  encoded (a `package.json` written as `"main": ".\/lib\/x.js"` failed to
  resolve); the escape decoder is now shared with the JSON parser, and
  malformed escapes in a `package.json` are treated as absent keys.
- The CJS named-export scanner now handles `exports['quoted']` /
  `module.exports['quoted']` assignments, does not treat `==` comparisons
  as exports, and the ESM facade exposes non-identifier names through
  string export names (`export { x as "quoted-key" }`) instead of emitting
  invalid syntax (which failed the whole module load).
- `DJS_MAX_FILE_SIZE` (documented) is now covered: numeric parse, junk
  falling back to the 512 MiB default, and EFBIG delivery.
- djs.json non-string value types (`true` grants, `null`/numbers are
  ignored) and structural errors (truncation, trailing garbage, nesting
  past the depth cap abort startup) are pinned by gate checks.
- A CLI flag for a category replaces that category's allow rules from a
  `-P` set (denies always merge) — the documented behaviour, previously an
  accidental union.
- A scoped `--allow-run` rejects `LD_*`/`DYLD_*` in a script-supplied
  child environment; unscoped grants pass them.
- The async (callback) fs surface was almost entirely untested — every
  suite fs assertion used the Sync variants, leaving the worker dispatch
  arms for stat/readdir/unlink/rename/realpath dark. `fs_async_ops.js`
  pins each operation's success and error delivery (ENOENT shapes,
  non-recursive `rm` = `EISDIR` like Node, worker-side writeFile errors),
  with order-stable output (results print in declaration order; completion
  order races between threadpool workers).
- `DJS_MAX_FILE_SIZE` overflow falls back to the default cap (added to the
  parse/junk/EFBIG checks).
- value.d's reachable helper arms: zlib stream-table exhaustion surfaces
  as `InternalError` (not a crash), and a throwing `toString` in a native
  argument (dgram bind host) surfaces as the pending exception.

`check-no-phase-refs.sh` no longer hangs when a FIFO exists under `tests/`
(it greps regular files only). Truncated chunked bodies reported complete; TE+CL smuggling shape accepted;
unbounded chunk buffering; TLS slot leaks; `net.detachFd` leaks; timer pool
unbounded; deadline-timer handle leak; `dgram.bind` gated by `listen`;
`--allow-listen` wildcards never matched; config `"deny": false` widened to
allow-all; `os.tmpdir()` threw instead of falling back to `/tmp`;
`readFileAlloc` silent 8 KiB truncation for files with a lying `fstat` size
(FIFOs, procfs); `pbkdf2`/keygen parameter bounds; net listen/dgram errors
returned instead of thrown; `process.arch` added; `utf16le` implemented;
`fetch` `AbortSignal`; `structuredClone` `__proto__`; legacy `Stream.pipe`;
`cpSync` symlinks; case-insensitive encoding names; arch-neutral goldens;
internal host paths scrubbed from docs; `SECURITY.md`/`CONTRIBUTING.md`
added; `bootstrap.sh` no longer hard-depends on `file(1)`.

## Validation

`dub test` (10 modules), `integration.sh` (171 cases, +13 new), the
permission gate (55 checks, +13 new), the net gate, and the ABI probe all
pass on Ubuntu 24.04 (LDC 1.36.0, libuv 1.48.0, arm64 and x86_64 CI).
