# v0.12.0 — crypto breadth

## Plan

Fill the crypto partial from `docs/COMPARISON.md`: ciphers and KDFs first,
then `sign`/`verify`/key objects. `sign`/`verify` moved to v0.12.1 because it
needs PEM key decoding, RSA/EC dispatch and a `KeyObject` surface; the cipher
and KDF layer stands alone and is what TLS/HTTP tooling actually calls.

Delivered: `createCipheriv`/`createDecipheriv` (AES-128/256 CBC and GCM, AAD,
auth tags), `pbkdf2`/`pbkdf2Sync`, `hkdfSync`, `scrypt`/`scryptSync`.

## Architecture

- One native entry point, `crypto.cipher(decrypt, alg, key, iv, input, aad,
  tag)`, performs the whole operation and returns `{data, tag}`. The JS Cipher
  class buffers `update()` chunks and calls it from `final()`. This avoids
  exposing an OpenSSL context across JS calls at the cost of streaming: a
  cipher cannot emit ciphertext incrementally.
- GCM uses `EVP_CIPHER_CTX_ctrl` for IV length, tag set/get; CBC relies on
  OpenSSL's default PKCS#7 padding.
- KDFs are one-shot natives using `PKCS5_PBKDF2_HMAC`, `EVP_PBE_scrypt`, and a
  manual HKDF built on the already-bound `HMAC_*` calls.
- Buffers are copied into `ArrayBuffer` results; all inputs go through
  `bytesAcquire`/`bytesRelease`, so typed arrays and strings share one path.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | HKDF via `EVP_PKEY_CTX_ctrl` segfaulted inside `EVP_MD_get0_name` on OpenSSL 3 | `hkdfSync(...)` | replaced with HMAC extract+expand, validated against RFC 5869 |
| 2 | high | `pbkdf2` was registered with 5 args but required 6, so every call threw | `pbkdf2Sync("password","salt",1,32,"sha256")` | argument check corrected |
| 3 | medium | bad GCM tags returned an `Error` object instead of throwing, so JS hit `r.data` and lost the code | tampered ciphertext | `throwError(makeError(...))`; code is now `ERR_CRYPTO_BAD_DECRYPT` |
| 4 | medium | `out` is a D keyword, so the first build failed | compile | renamed to `outp` |
| 5 | low | `setAutoPadding` cannot turn padding off | API shape | documented as PKCS#7-only, GCM unaffected |
| 6 | low | ciphers are one-shot; `update()` returns empty | streaming use | documented; streaming context is future work |
