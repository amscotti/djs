# v0.12.3 — fs.watch

## Plan

Deliver the first half of batch 3: `fs.watch` on inotify. `dns.resolve*`, `vm`,
WebSocket client, Web Streams and `fs.opendir` move to v0.12.4 so this release
has one owner, one failure mode and a real event-loop test.

## Architecture

- One `WatchSlot` per watcher (32 max) holds the inotify fd, watch descriptor,
  libuv poll handle, runtime and callback registry id.
- `inotify_init1(IN_NONBLOCK|IN_CLOEXEC)` + `inotify_add_watch` on the path;
  the fd is polled with `UV_READABLE`.
- The poll callback drains the fd once, walks `struct inotify_event` records
  and emits `(eventType, filename)`. `IN_MODIFY|IN_ATTRIB` map to `change`;
  create/delete/move map to `rename`, matching Node's coarse contract.
- `close()` releases the callback slot, stops the poll handle and lets the
  handle-close callback close the fd, so libuv never sees a closed descriptor
  it still owns.
- JS `FSWatcher` extends `EventEmitter`, emits `change` and invokes the
  listener, then `close`.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | `watchStart`/`watchClose` were not added to the install chain (`rmSync` takes 3 args, the patch targeted 2) | `typeof __djs.fs.watchStart === 'undefined'` | registered explicitly |
| 2 | high | the fd was closed before `uv_close` completed on the first draft | close during an event | fd closes in the handle-close callback |
| 3 | medium | `JS_NewString` does not exist in the bindings | build | `JS_NewStringLen` + `strlen` |
| 4 | medium | `throwFsError` needs `(ctx, err, path, syscall)` | build | pass the watched path |
| 5 | low | recursive watching is ignored | `fs.watch(dir, {recursive:true})` | documented; inotify needs per-directory watches |
| 6 | low | watch table is fixed at 32 | many watchers | documented limit; error is explicit |
