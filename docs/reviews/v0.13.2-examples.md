# v0.13.2 — Express/Hono example apps and fetch gaps

## Plan

Validate the runtime against real frameworks instead of synthetic routes, using
one UI twice: Express (already a gate target) and Hono (new). The app is a
five-step job whose progress the backend pushes as HTMX fragments polled every
400 ms; Alpine owns theme state and a fragment counter.

## Architecture

- Shared static assets (`index.html`, `app.css`, vendored htmx 2.0.4 and
  Alpine 3.14.8) under each example's `public/`.
- Express example: `express.static` + three routes (`/start`, `/progress`,
  `/api/status`), in-memory job driven by `setInterval`.
- Hono example: same routes; a hand-written adapter buffers the request body
  and calls `app.fetch(new Request(url, {method, headers, body}))`, then copies
  status/headers/body onto `res`. `@hono/node-server` itself needs Node stream
  conversions that djs does not expose.
- Polling stops without extra JS: the finished fragment omits `hx-get`, so the
  `outerHTML` swap replaces the polling element with a terminal one.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | `Request` was not a global; Hono failed at `new Request(...)` | `app.request("/")` | `Request` constructor in the prelude |
| 2 | high | `Headers` lacked `set`/`append`/`delete`; every `c.header()` threw | Hono `c.header("content-type", ...)` | full Headers method set |
| 3 | high | `Response` treated a `Headers` instance as a plain object, producing a header named `_map` | `new Response(body, {headers: h})` | constructor copies `FetchHeaders` / `forEach` objects |
| 4 | medium | Hono's `app.fetch` returns `Response` synchronously (its `#dispatch` is not async); adapter assumed a promise | `app.fetch(req).then` → not a function | `Promise.resolve(app.fetch(...))` |
| 5 | low | Alpine `x-on:htmx:afterSwap.window` did not update the counter, though a raw `window` listener saw the events | `swaps` stayed 0 | `x-init` + `addEventListener` |
| 6 | low | missing favicon caused a 404 console error | page load | `<link rel="icon" href="data:,">` |
