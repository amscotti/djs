# v0.12.7 — Web Streams

## Plan

Close the Web Streams partial with the core three classes and `pipeTo`.
Byte streams/BYOB, queuing strategies and encoding streams stay out; they need
a buffer-pool design, not a queue.

## Architecture

- `ReadableStream` owns a chunk queue, a pending-read list and a source. The
  controller exposes `enqueue`/`close`/`error`/`desiredSize`. `_flush` resolves
  pending reads from the queue, then closes or rejects them, then asks the
  source for more. `pull` runs only when the queue is empty and not already
  pulling, which is the backpressure contract.
- `WritableStream` serializes writes on a promise chain; `close` appends the
  sink's close, `abort` bypasses the chain.
- `TransformStream` wires a readable controller into a writable sink; the
  transform's return value is enqueued, `flush` runs before close.
- `pipeTo` is a read→write loop that awaits each write, so a slow sink slows
  the reader.
- Async iteration delegates to `getReader().read()`.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | a pull-driven source can recurse: `pull` → `enqueue` → `_flush` → `_maybePull` | `pull` implementation | `_pulling` guard plus queue-length check |
| 2 | medium | resolving reads after close must resolve `{done:true}`, not reject | read after close | explicit closed branch |
| 3 | medium | write chains poison after one rejection | failing sink write | documented; stream errors are terminal, matching Node |
| 4 | low | `desiredSize` is a queue-length heuristic, not a queuing strategy | design | documented |
| 5 | low | `TransformStream` accepts only function-style transformer | design | documented |
