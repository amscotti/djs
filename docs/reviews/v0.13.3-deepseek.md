# v0.13.3 — DeepSeek via the OpenAI SDK

## Plan

Answer "can djs run a real AI client?" with an actual API call, not a mock.
`examples/deepseek-chat` uses the official `openai` SDK against DeepSeek, one
buffered completion and one streamed completion. Every gap it exposed is fixed
in the runtime, with a local regression test.

## Architecture

- `chat.js` builds `new OpenAI({apiKey: env.DEEPSEEK_API_KEY, baseURL})` and
  calls `chat.completions.create` twice (normal and `stream: true`).
- The SDK talks through the prelude's `fetch`, which now resolves at response
  headers and exposes `Response.body` as a `ReadableStream`.
- `Response.text/json/arrayBuffer` drain that stream through a shared
  `_consume()` and cache the buffer, so existing buffered callers (Hono
  adapter, examples) keep working.
- `FormData` is a minimal implementation; `Headers` is iterable; `ClientRequest`
  unwraps `Headers` by `forEach` and copies only own properties.

## Application review

| # | Severity | Finding | Reproduction | Fix |
|---|---|---|---|---|
| 1 | high | `FormData is not defined` at SDK `buildBody` | any SDK request | `FormData` global |
| 2 | high | `[...headers]` threw — `Headers` had no `Symbol.iterator` | SDK request logging | iterator over `entries()` |
| 3 | high | `for (var k in options.headers)` walked `Headers` prototype, sending `append`/`set` function source as header values | `invalid character in HTTP header value: append len=169` | `hasOwnProperty` + `instanceof FetchHeaders` unwrap |
| 4 | high | SDK stream failed with `Attempted to iterate over a response with no body` | `stream: true` | `Response.body` stream + draining accessors |
| 5 | medium | HTTP client buffers the whole response, so the body stream yields one chunk at the end | `fetch_stream` shows `chunks 1` | documented; SSE parsers still split events correctly |
| 6 | low | header validation error did not name the header | debugging | message now includes name, length, index, char code |

## Verification

- Real API (key from the environment, never printed):
  - buffered: `model deepseek-flash`, usage `24/27`, latency ~1.2 s, a correct
    one-sentence QuickJS answer
  - streamed: `"1, 2, 3, 4, 5"` from 15 SDK chunks
- `tests/js/fetch_stream.js` + golden: `status 200`, `response.body.getReader`
  is a function, two SSE-style lines parsed (`sse true one|two`), `chunks 1`
  documenting the buffering limitation.
- `tests/js/fetch_headers.js` still green; examples smoke (Express + Hono)
  still green.
